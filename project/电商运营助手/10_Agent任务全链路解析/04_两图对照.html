基础图与平台图的业务流程对照

共享骨架相同，入口裁决与最终构图不同

总体结论：两条流程并非「除了入口以外都一样」。它们共享「写入发件箱 → Worker 扫描投递 → 构图执行 → 状态机与检查点」这套运行时骨架；但在工作流如何裁决、校验多少、最终构建哪张图上有实质差异，而且存在一条回流路径——平台入口若路由到商品诊断，最终执行的仍是基础图。

二、五处关键差异

环节基础图链路平台图链路
入口POST /products/{product_id}/agent-runs，从商品工作台发起POST /workspaces/{workspace_id}/agent/tasks，从平台工作台发起
工作流裁决写死 product_diagnosis_optimization，不做意图路由显式 workflow_key 或 route_intent(intent) 裁决，可选注册的七条工作流
Task 创建条件创建：商品所属工作区启用该工作流才建，否则 task 为空并直投队列必建：同一事务写四张表，无“跳过”分支
校验仅做活动运行冲突检查工作区准入、上下文作用域、对话、每租户并发上限等多重校验
最终构图固定构建基础图 build_product_operation_graph默认回落基础图；其余六条工作流才构建平台图 build_platform_workflow_graph
共享部分：两条链路都写 OutboxEvent 并走两阶段投递，都由 agent.workflow Worker 消费，都用 thread_id + 检查点实现中断恢复，都用租约防止重复执行。两者的差异集中在入口与构图，运行时骨架相同。
